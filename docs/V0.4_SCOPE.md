# V0.4 落地范围：Evidence Layer

V0.4 不增加新的成员入口，而是在现有 `sources/` 与 `.knowledge/records/` 中补齐“来源 → 解析 → 证据片段 → 知识候选/正式知识”的可核查契约。

## 设计来源

V0.4 保留 project-wiki 与 llm_wiki 已有融合，同时吸收 WeKnora 在以下方面的启发：

- 来源身份与来源修订分离；
- 来源逻辑路径与本地存储位置分离；
- 处理配置与解析器版本可追溯；
- Chunk 保留章节、原文位置和来源修订；
- 原始解析结果与人工纠正分离；
- 候选/正式知识先绑定具体证据，再组织语言；
- 解析、证据、索引、编译、发布是不同阶段事实。

WeKnora 参考提交：
`Tencent/WeKnora@7fa6f028fcea9e08720db1f565ec4911ea0e7aa6`。

本版本只吸收上述机制并自行实现，不复制 WeKnora 源码。

## 已实现

### 1. 稳定来源身份

`team-wiki ingest` 新增：

```
--connector
--upstream-id
--logical-path
```

当存在 `connector + upstream_id` 时：

- `source_id` 由稳定上游身份生成；
- 内容变化不会生成新的 source_id；
- 相同上游身份 + 不同内容必须使用 `refresh-source`；
- 文件改名或本地副本名变化不会被当成新来源。

没有可靠上游身份的手工投递，仍使用内容哈希作为去重 fallback。

`source.yml` 新增 `origin`：

```yaml
origin:
  identity_mode: upstream
  connector_id: git
  upstream_id: project-a:docs/import.md
  logical_path: 订单系统/接口规范/批量导入
```

本地资料包路径仍按首次登记时间稳定保存，逻辑路径只用于导航和来源语义。

### 2. 版本化处理记录

每次 Text/Markdown intake 生成：

- `manifest.json`；
- `processing.yml`；
- immutable chunk Markdown；
- `review-progress.yml`。

`processing.yml` 记录：

- source_id / source_revision；
- processing_id；
- parser name / parser version；
- effective_config；
- 覆盖范围与 warnings；
- processing state。

修改标签等非内容字段不会要求重新解析；来源修订会生成新的 intake/processing 身份。

### 3. 结构化 Evidence Chunk

每个解析片段现在具备：

- evidence_id；
- source_id；
- source_revision；
- processing_id；
- chunk id / sequence；
- content sha256；
- logical_path；
- heading_path；
- char_start / char_end；
- index_state。

正式知识与证据不再只通过“引用整个文档”关联。

V0.4 仅对解析器确实能确定的字符位置和 Markdown 标题路径负责，不伪造 PDF 页码、表格坐标等定位。

### 4. 原始解析与人工纠正分离

新增：

```
team-wiki evidence-show
team-wiki evidence-correct
```

纠正不会修改 parser 输出的 chunk 文件，而是生成：

`.knowledge/records/evidence-corrections/CORR-*.yml + .md`

记录：

- evidence_id；
- previous/new sha256；
- reason；
- verified_by；
- source revision；
- processing_id。

读取证据时默认返回最新纠正结果，同时保留 raw_text 与 raw_sha256。

来源重新解析后会得到新的 evidence_id；旧纠正继续保留历史，不会静默套用到新解析结果。

### 5. Evidence Binding

新增：

```
team-wiki evidence-bind
team-wiki evidence-bindings
```

支持将 evidence chunk 与以下目标关联：

- candidate；
- knowledge；
- change；
- review。

关系：

- supports；
- limits；
- contradicts；
- relevant。

该绑定是“具体证据与结论对象”的结构化关系，不替代语义审核。

来源内容更新时，影响分析现在同时检查：

1. 正式知识 frontmatter 的 source 引用；
2. evidence binding 到正式 knowledge 的关系。

### 6. 来源处理阶段状态

新增：

```
team-wiki source-status <root> <source_id>
```

返回：

- acquisition；
- processing；
- evidence；
- indexing；
- knowledge_change。

当前 V0.4 的向量/全文派生索引尚未接入，因此 Evidence Chunk 默认 `index_state=not-indexed`，不会因为“解析成功”伪装成“已可检索”。

## 仍未实现

- Git 项目 connector 的增量列举与删除判断；
- PDF / DOCX / 图片 / 表格解析；
- 父子 chunk 检索；
- Evidence Candidate 自动抽取；
- 自动从 evidence bindings 生成知识 Patch Plan；
- 向量索引 / LanceDB；
- 语义级“旧来源贡献撤回”；
- 自动修改正式 Wiki；
- 外部文档平台连接器；
- 多资料按目标知识批次归并。

## 重要边界

- Source ≠ Knowledge；
- Parser output ≠ 原始文件；
- Evidence Chunk ≠ 正式知识；
- Evidence binding ≠ 语义正确性证明；
- Parsing complete ≠ Index ready；
- Index ready ≠ Knowledge compiled；
- Knowledge compiled ≠ Published；
- Published ≠ 后续真实采用和验证。
