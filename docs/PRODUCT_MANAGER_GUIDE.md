# 成员使用指南

知识库应帮你把眼前的事做得更快、更稳，而不是要求你学习另一套系统。

## 遇到问题，直接说正在做什么

> 这个项目出现了依赖版本不更新的问题。查一下项目和团队已有经验，读原文后告诉我适用条件、下一步和来源。

当前 Agent 应查找已接入资料，再读原文回答。你不需要知道文件名、仓库结构或管理命令。普通浏览也可从现有团队导航和项目文档进入。

有相似经验不代表原因完全相同；Agent 应说明哪些条件已确认、哪些只是检查方向。没有找到时仍可继续排查代码和日志，但应区分本次分析和团队已经确认的结论。

若资料未接入、文件不能读取或权限不足，应当明确告诉你，而不是说“团队没有这条知识”。首次接入、工具安装和本机路径由有权限的维护者处理；不是每位成员都要操作的任务。

## 做完一件事，不必重新交一份知识作业

> 这次已经确认是配置覆盖导致的问题。利用刚才的排查记录，补充原来的说明，保留现象、原因、解决方法、适用环境和验证依据。

先找已有内容，有对应文档就最小补充；没有必要的新信息就正常结束。不为每次工作新建文档、填写采用记录或重复解释工作过程。

项目设计与踩坑留在原位置。确实能帮助其他项目的结论，再提炼到团队库并引用项目来源，不复制一整份项目文档。

## 交资料，只需附上用途和来源

> 这份材料与退款口径有关，来源是本次评审。请先查已有说明，提取需要补充或修正的部分，不要把未确认的推测写成事实。

团队资料可交到现有 `sources/inbox/` 或约定入口。原始材料可以只作为参考，不要求每份都转成正式知识，也不用先登记证据、创建变更对象。

当前工具不会直接解析 PDF、Word 或图片。已有 Agent 有相应读取能力时可协助，否则需要人工摘取可核查内容并保留原件。上传不等于已读懂、已处理或已审核。

## 发现错误，在原处纠正

> 这条经验在我们当前版本不成立。依据是本次测试记录，请核对原来的适用范围，提出修订，不要另写一篇互相冲突的结论。

Agent 准备差异，说明改了什么和依据；重要结论由现有责任人确认，沿用已有审核渠道。你的只读权限不会因此扩大；可以通过已有沟通或评论渠道提出问题，再由有权限的人修改。

团队库 README 应说明谁确认、在哪里审核。未明确时，Agent 只能说明已准备修改，不能声称已经有人接手或已经审核。没有持续运行的 Agent，也不会自动处理新资料。

## 什么情况下值得信任

能定位原文和来源，适用版本与业务条件匹配，已确认内容与推断能够区分。仅仅位于某个目录、标成 active、格式检查通过或搜索排名第一，都不是正确性的证明。

你指出“答案不适用”“应该有但没找到”，就是有价值的反馈。Agent 可以顺手准备检索回归用例，不需要你学习评测文件格式。

长期没修改不等于过期，没有使用记录不等于无人使用。是否保留、修正或提炼，应看实际价值和依据，而不是为了清空工具提示。
