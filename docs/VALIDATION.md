## 文件优先检索

按用户要求，已撤掉 SQLite、持久检索缓存和索引同步。此前的数据库冷/热查询测量不再代表当前实现，已从现行验收移除。

`search`、`related` 和 `context` 直接读取当前配置范围内的 Markdown；一次 `context` 调用只复用本次读到的文档。Git 更新或文件增删改后无需刷新数据库；旧数据库文件不读取、不改写、不删除。

文件检索专项覆盖 12 项行为：中文与无关负例、状态和范围筛选、项目配置范围变化、精确 ID、增改移删、显式关系、无文件写入、旧数据库完全不访问、元信息错误与重复 ID、持续读取漂移，以及真实隔离 Git 仓库切换分支后的即时读取。

安装后的 CLI 在本轮临时项目中验证了：修改正文后无需任何刷新即可查到新内容，旧查询不再命中；search/context 前后文件内容一致；故意保留的无效旧数据库字节未改变。context 的回归确认单次调用中每篇文档只解析一次，下一次调用会重新读取。

## 检索容错与首轮评测

- 坏文件（YAML 错误、读取漂移）改为跳过并报告，重复 ID 保留检索并报告；原先“任一文件出错则整体失败”的测试已改写。全量测试 134 项通过。
- 用 ReportHub 副本（`.tmp/eval-sample`，只读来源）建立 15 条用例（13 正例、2 负例）。结果：recall@5 = 1.0，MRR = 0.823，负例通过 1/2。
- 失败项：“员工请假流程审批”在无关库中返回 5 篇文档，原因是“流程”“审批”等泛词的 2-gram 单独可得分。这是排序需要改进的证据，尚未调整。
- 局限：样本仅 12 篇，用例由实现者根据文档内容编写，偏乐观。真实提问需由团队成员积累后重新测量；在有更多用例前不对排序参数调优。
