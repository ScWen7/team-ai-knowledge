# V0.9：分层知识治理与可验证检索

状态：已按用户决定移除 SQLite 层，文件优先检索工程验证完成；真实多人试点待执行。验证结果见 `VALIDATION.md`，现行产品契约以 `FINAL_DESIGN.md` 为准。

## 目标与边界

同时服务 AI 开发标准化、事实经验持久化、非技术成员低成本维护、持续准确高效四项目标。

- 团队库维护团队域；项目库维护项目设计、决策、踩坑和证据。
- 初始化项目时治理存量文档；格式整理不改变知识有效性，不把项目特例升级为团队规则。
- 普通知识查阅无需创建 Work。显式项目底线仍完整读取并通过 start/release 检查。
- 不修改 ReportHub 文档、远端系统、现有真实知识记录，不提交或部署。

## 实现范围

1. 项目文档治理：指定或发现文档目录、只读预览、补齐可确定元信息、保留原正文、列出待确认项、生成独立导航、重复执行无额外改动。
2. 项目接入：`project-init` 支持文档治理；团队底线订阅可独立配置；`project-rules` 完整返回已锁定的底线正文并验证版本，日常检索无需 Work。
3. 检索：兼容团队 wiki 与项目文档目录；直接读取当前文件，按状态/范围筛选；保留中文检索和显式关系；Git 更新和文件增删改无需索引同步；查询不创建、读取或清理数据库缓存。
4. 简化：删除没有真实使用依据的 Batch、启发式关系推荐和 Node.js 运行依赖；显式关系保留。旧 budget 入口仅保留兼容结果并标明不执行上下文裁切。
5. 维护：移除机械内容运营工作流和不实自动化承诺；状态只表达实际观测；普通贡献通过已有 Git 审核渠道或当前 Agent 完成。原有高级证据/变更协议保持兼容，避免静默破坏历史数据。

## 验收

- 治理预览不写文件；应用只修改明确范围；正文与既有元信息保留；二次应用无差异；越界路径、符号链接和损坏 YAML 不被写入。
- ID 重复、链接缺失、未知有效性和责任归属可见；整理不制造 owner、verified 或 active。
- 普通项目文档可在原目录被检索；团队知识和项目知识不复制合并。
- 显式底线不经 Top-K，锁定正文 hash 与 commit 一致；已有 must-address/review-required 及中途锁变更回归继续通过。
- 检索无关内容不因类型被推荐；Git 更新、增改删、过滤和只读行为有回归；以固定语料测量文件查询及修改后的查询，并披露样本规模和限制。
- 运行全部单元测试和安装后的 CLI；只读盘点 ReportHub 样本；不把这些证据写成真实多人协作或生产验收。
