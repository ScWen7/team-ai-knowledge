# V0.2 落地范围

V0.2 的目标不是扩目录，而是首次把两个上游的能力接到统一知识闭环。

## 已实现

1. **project-wiki 的确定性来源范围机制（适配版）**
   - 仓库内路径规范化；
   - `.project-wiki/.wikiignore` 过滤；
   - 符号链接/仓库外路径防护；
   - UTF-8 源文件 list/read/search。

2. **llm_wiki 的纯知识计算（适配版）**
   - `context-budget`：保持字符预算语义和上游边界公式；
   - `graph-relevance`：保留 direct link / shared source / common neighbor / type affinity 四类信号；
   - 去掉 Tauri 文件系统、basename 身份、桌面缓存；输入改为统一的稳定 knowledge ID 节点。

3. **Work → Evidence → Observation → Change**
   - `prepare` 创建 W；
   - `adopt` 记录真正采用的知识及其内容摘要；
   - `evidence` 创建证据记录；
   - `observe` 区分 supported / boundary / contradicted / not-applicable / not-verified；
   - `finalize` 对 boundary/contradicted 创建 CHG，并把 W、K、E 串起来。

4. **检索计划**
   - `search` 提供直接候选；
   - `related` 用适配后的 llm_wiki 关系计算补充候选；
   - `context` 返回预算、直接候选和关系候选，不代替当前 Agent 作答。

## 本地验证

在 Python 3.13 / Node.js 22 环境执行：

```
PYTHONPATH=src python -m unittest discover -s tests -v
```

共 5 个测试通过，覆盖 V0.1 回归、预算/关系、安全来源范围和 W/E/CHG 闭环。

## 仍未实现

- 自动修改正式知识正文；
- Review 的持久重开与阻塞范围；
- 来源变更的完整依赖传播；
- project-wiki 文档解析/分块进度代码的实际接入；
- llm_wiki graph-insights / research-topic 的代码接入；
- LanceDB 和 embedding；
- MCP / 桌面 UI；
- CI/PR 门禁。

## 许可门槛

V0.2 开始包含基于固定上游代码适配的模块：

- `scope.py`：基于 project-wiki MIT 源码结构适配；
- `knowledge_core/*.mjs`：基于 llm_wiki GPLv3 代码适配。

**V0.2 采用 GNU GPL v3 作为整个仓库的分发许可证，并保留 project-wiki 的 MIT 声明和 llm_wiki 的 GPLv3 来源/修改说明。** 该选择用于当前公开仓库的工程合规，不替代组织自身的法律审查。
